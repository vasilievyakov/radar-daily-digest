# Радар — клиент для macOS

Меню-бар приложение на SwiftUI. Читает один JSON-файл, который пишет ядро, и
рисует его. Больше ничего не умеет: ни сети, ни базы, ни модели, ни ранжирования
(MAC-2, SUR-1, SUR-2). Это и есть архитектурный аргумент демо — граница между
ядром и поверхностью проходит по контракту `Signal`, а не по договорённости.

## Сборка и запуск

    ./build.sh          # собирает build/Radar.app
    open build/Radar.app

## Где берутся данные

По умолчанию `~/Demo Challenge/out/signals.json` — его пишет `build_site` при
каждом прогоне, рядом с тремя HTML-страницами. Переопределяется:

    RADAR_FEED=/путь/к/signals.json open build/Radar.app

или через меню в приложении: «Выбрать файл сводки…».

Файл отслеживается: как только прогон допишет его, окно обновится само. Раз в
20 секунд идёт добор опросом — на случай, если событие файловой системы
потеряется.

## Окно и меню-бар

Приложение ставит item в меню-бар (MAC-1) и открывает окно. Окно — потому что
на этой машине меню-бар переполнен: macOS создаёт item (`isVisible = true`,
кадр получен), но кладёт его слева от выреза и не рисует, без всякого указания,
что что-то скрыто. Минимальный AppKit-item ведёт себя так же, то есть дело не в
приложении. Если меню-бар свободен, окно отключается:

    RADAR_WINDOW=0 open build/Radar.app

## Проверки

    swift run RadarChecks

Гоняет декодер по настоящей сводке последнего прогона и по трём фикстурам —
обычная карточка, тихий день, несостоявшийся прогон. Фикстуры генерируются из
ядра, а не пишутся руками:

    .venv/bin/python macos/regenerate-fixtures.py

Ни XCTest, ни swift-testing на этой машине нет — установлены Command Line Tools
без Xcode, поэтому проверки сделаны отдельным исполняемым таргетом, который
возвращает ненулевой код.
