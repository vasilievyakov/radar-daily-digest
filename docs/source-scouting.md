# Разведка источников

Дата проверки: 2026-08-17. Каждый адрес в таблицах открыт curl-ом
(`curl -sS -L --max-time 25`), размер и число уникальных дат измерены,
а не оценены. Кандидаты, которых не существует, вынесены в отдельный раздел.

Уникальные даты считались по двум шаблонам: `2026-08-17` и `August 17, 2026`.
Там, где страница использует другой формат (месячный заголовок плюс день,
атрибут `dateTime`, поле `date` во встроенном JSON), это оговорено отдельно
и приведено фактическое число датированных записей — сырой счётчик в таких
случаях занижает содержимое в разы.

## Важное техническое наблюдение

Домен `ai.google.dev` отдаёт содержимое **только при пользовательском агенте
curl по умолчанию**. Если подставить строку браузера (`Mozilla/5.0 ... Chrome/124`),
сайт уводит запрос в цепочку OAuth-редиректов на `accounts.google.com`
и curl обрывается на пятидесятом переходе. Это ровно тот случай, когда
«умная» маскировка под браузер ломает сбор. Адаптер `html_scrape` не должен
подставлять браузерный User-Agent для этого домена.

Отдельно: `cloud.google.com/vertex-ai/...` перенаправляет на
`docs.cloud.google.com`, а `docs.claude.com/en/release-notes/overview` —
на `platform.claude.com/docs/en/release-notes/overview`. Оба редиректа
отрабатывают штатно, но во втором случае итог совпадает с уже
подключённым `docs.claude.com/en/release-notes/api`: это одна и та же
страница, добавлять её как второй источник бессмысленно.

### Что это значит для демонстрации тренда

Материал для содержательного наблюдения в данных есть, и он сосредоточен
в трёх местах.

Первое — отключение моделей как сквозной отраслевой сюжет. Anthropic, OpenAI
и Google ведут одинаковые по устройству реестры: модель, дата объявления,
дата отключения, рекомендуемая замена. Три вендора, у каждого больше десяти
событий за год, сопоставимая структура. Это единственный тренд, который
можно показать в разрезе «одно и то же происходит у всех».

Второе — GitHub сам по себе. Его лента изменений даёт плотность сразу
в четырёх типах, включая цены и лимиты, и это единственный вендор,
у которого не пустует ни одна из четырёх ключевых ячеек.

Третье — цены и лимиты вокруг агентных тарифов. Anthropic (24 события),
GitHub (23), Cursor (4), LangChain (6 по лимитам) за последний год
неоднократно меняли условия тарификации агентов. Тема набирается,
хотя источники разнородны и требуют разных разборщиков.

Признать безнадёжными приходится двоих. У MCP датированной истории нет
в принципе: за всё существование протокола вышло пять ревизий спецификации,
и никакой парсер не превратит две ревизии за год в тренд. У n8n есть
превосходная история релизов и содержательные документы о ломающих
изменениях, но одно с другим не связано датами: страницы `v20-breaking-changes`
и `v30-breaking-changes` перечисляют десятки пунктов, ни у одного из которых
нет собственной даты. n8n останется вендором с плотной ячейкой релизов
и пустыми остальными — то есть ровно тем случаем, который в записке назван
несодержательным наблюдением.

Cursor занимает промежуточное положение. Его цены — реальный сюжет
с шестью событиями за четырнадцать месяцев, но добыть их можно только
разбором JSON, вшитого в страницу блога. Заявленная лента изменений
для этой цели непригодна, и рендеринг ничего не меняет.

## Что добавить в конфигурацию в первую очередь

1. `https://github.blog/changelog/` для суточного окна и шаблон
   `https://github.blog/changelog/{ГГГГ}/{ММ}/` для обратного заполнения.
   Закрывает четыре ячейки одного вендора разом.
2. `https://ai.google.dev/gemini-api/docs/deprecations`. Закрывает
   `google × deprecation` целиком и достраивает межвендорный сюжет
   об отключении моделей до трёх участников.
3. `https://changelog.langchain.com/`. Единственный источник,
   выводящий LangChain из нуля сразу в трёх ячейках.
4. `https://docs.github.com/en/graphql/overview/breaking-changes`.
   Реестр запланированных отключений с датами вплоть до января 2027.
5. `https://cursor.com/blog`. Закрывает `cursor × pricing` — иначе
   у Cursor не набирается ни одной плотной ячейки.

Следом, вторым эшелоном: `https://ai.google.dev/gemini-api/docs/changelog`,
`https://docs.n8n.io/release-notes/`,
`https://docs.langchain.com/langsmith/self-hosted-changelog`,
`https://platform.openai.com/docs/changelog` (с двухуровневым разбором дат)
и `https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes`.
