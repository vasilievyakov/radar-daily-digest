## 0. Контекст срочности

Демо перед аудиторией — завтра. Это меняет приоритеты: незавершённая, но честная часть лучше завершённой имитации. Ничего не мокать, ничего не подставлять руками. Все артефакты, которые пойдут на экран, должны быть результатом реальных прогонов.

Если что-то не успевает — оно вырезается из демо целиком, а не достраивается заглушкой.

## 1. Три решения, которые нельзя откатить

Ошибка в любом из трёх не чинится правкой кода — только повторным бэкфиллом, на который нет ни времени, ни бюджета. Принять до написания кода стадий.

### 1.1 Схема Signal — до запуска бэкфилла

PRD, раздел 5.7. Требования PUB-2 и SIG-1 критичны:

- В Signal не сохраняются строки, обрезанные под лимит канала
- В Signal нет разметки Telegram и HTML письма
- `headline` и `summary` — полные

Если сигнал ляжет в базу в телеграм-формате, дашборд и нативный клиент станут непостроимыми на уже собранных данных.

### 1.2 Нормализация метаданных — до первого запроса к источникам

Словарь `vendor` и `change_type` фиксируется в конфиге и применяется единообразно. `anthropic`, `Anthropic` и `claude` как три разных значения ломают фильтрацию ретривала (FR-6.13), и обнаруживается это только когда корпус уже собран.

### 1.3 Транспорт хранилища сигналов — до написания любой поверхности

Открытый вопрос №10 в PRD. Файл в синхронизируемой папке, локальный HTTP или удалённый эндпоинт. Определяет, сможет ли Swift-клиент вообще читать данные. Решение занимает минуту, его отсутствие блокирует пункт 8 плана работ.

## 2. Роутинг моделей: сборка

Дефолт — Opus 5. Fable 5 не использовать: он вдвое дороже ($10/$50 против $5/$25) и проигрывает Opus 5 семь из восьми опубликованных прямых сравнений. Эскалация на Fable — только если Opus измеримо не справился с конкретной задачей.

| Задача | Модель |
|---|---|
| Схема Signal, контракт хранилища, границы слоёв | **Opus 5** |
| Промпты извлечения фактов и разметки трендов | **Opus 5** |
| Адаптеры источников (14 шт.) | Sonnet 5 |
| Скрипт бэкфилла, индексация, тесты | Sonnet 5 |
| Swift-клиент | Sonnet 5 |
| Форматтеры Telegram / email | Sonnet 5 |

Правило разделения: Opus там, где решение однократное и неисправимое; Sonnet там, где работа объёмная и по готовой спеке.

**Не вести длинные интерактивные итерации на дорогой модели.** Тридцатиминутная сессия с мелким пинг-понгом легко даёт 50K+ токенов; при $50/M на выходе это $2–3 за разговор, который дешёвая модель проводит за $0.15. Обсуждение — Sonnet, переключение на Opus под конкретное решение.

## 3. Роутинг моделей: рантайм пайплайна

Определяет, влезает ли прогон в целевые $0.50 (NFR-5).

| Стадия | Модель | Обоснование |
|---|---|---|
| 1. Сбор | — | Достаточно кода |
| 2. Кластеризация | Haiku 4.5 | Механическое сходство, большой объём |
| 3. Фильтр релевантности | Sonnet 5 | Проходит через каждый материал |
| 4. Обогащение | **Opus 5** | Точность даты и версии критична, объём мал |
| 5А. Краткосрочная дельта | — | Детерминированное сопоставление, без модели |
| 5Б. Тренды и контекст | **Opus 5** | FR-6.16 не выполним на слабой модели |
| 6. Скоринг | Sonnet 5 | Ранжирование по заданным весам |
| 7. Публикация | — | Сборка структуры |

Принцип: дорогая модель работает только там, где ошибка публикуется наружу. На стадиях 2–3 объём в разы больше, а цена ошибки — один пропущенный материал.

Модель каждой стадии выносится в конфиг, не хардкодится.

## 4. Стоимость

**Кэширование префикса.** Критерии релевантности, словарь вендоров и описание предметной области одинаковы для всех материалов прогона. Выносить в кэшируемый префикс: попадание в кэш стоит 10% от обычного входа.

**Batch API — 50% скидки на вход и выход.** Бэкфилл ложится в этот режим идеально: он не чувствителен к задержке.

**Но не при первом бэкфилле.** Batch асинхронный. Если он вернётся после начала вебинара, корпуса не будет вообще. Первый бэкфилл — синхронно, полная цена. На batch переходить со следующего расширения корпуса.

**Лимит стоимости обязателен на входе в бэкфилл** (FR-6.8). Запуск без лимита не производить.

## 5. Порядок работ

Строго последовательно по зависимостям. Пункты 1–3 блокируют всё остальное.

1. **Схема Signal** — Opus. До всего остального
2. **Скелет хранилища сигналов, запись прогона** — Sonnet
3. **Промпт извлечения фактов** — Opus. Один, вылизанный, с обязательной цитатой-подтверждением
4. **Адаптеры GitHub Releases + changelog'и** — Sonnet, параллельно
5. **Бэкфилл** — синхронно, с лимитом стоимости
6. **Выявление трендов по корпусу** — Opus
7. **Форматтеры и доставка Telegram / email** — Sonnet
8. **Swift-клиент** — Sonnet, только если 1–7 закрыты

**Пункт 8 отрезается без сожаления. Пункт 1 не отрезается никогда.**

## 6. Скоуп бэкфилла

PRD, раздел 6.1. Повторить явно, потому что соблазн расширить велик:

**Качать:** GitHub Releases API (полная история через пагинацию), changelog'и и release notes вендоров (месяцы на одной странице).

**Не трогать:** медиа, агрегаторы, Telegram, RSS-архивы. Они не бэкфиллятся дёшево и наполнят корпус естественно за недели ежедневных прогонов.

Расширение скоупа бэкфилла на медиа — самый вероятный способ не успеть к демо и остаться вообще без корпуса.

Цель: не менее 300 EventStatement, глубина не менее 6 месяцев.

## 7. Запреты

Нарушение любого из них уничтожает продуктовый или демонстрационный аргумент.

**Факт без подтверждения не публикуется** (FR-4.3). Не удалось извлечь дату — поле пустое, в карточке «дата в источнике не указана». Домысливание запрещено.

**Утверждение о тренде без списка записей не публикуется** (FR-6.16–6.19). «Вендор всё чаще» и «наблюдается тенденция» — запрещённые формулировки. Допустимо только «третий раз с мая» с приложенными тремя записями с URL и датами. Ретривал вернул менее двух подтверждений — метка `isolated`.

**Логика не протекает в поверхность** (SUR-2, MAC-2). Поверхность не фильтрует, не переранжирует, не обращается к модели, не вычисляет тренды. Она рисует. macOS-клиент должен быть демонстративно тупым — в этом весь его смысл.

**Ядро не знает о поверхностях.** Пайплайн заканчивается записью в хранилище сигналов. Импорт telegram-библиотеки внутри стадий 1–7 — признак нарушенной архитектуры.

**Тихий день доставляется** (PUB-4, SUR-4). Отсутствие сигналов — тоже сигнал. Это ключевой момент демо, а не краевой случай.

**Контент источников — данные, не инструкции** (NFR-13). Тексты материалов не влияют на поведение агента.

## 8. Что должно работать к моменту демо

Минимальный набор, ниже которого демо теряет смысл:

- Корпус с реальной глубиной и видимым объёмом
- Хотя бы один сигнал с меткой `recurring` или `trend_member` и раскрываемым списком прецедентов (DR-8)
- Хотя бы один кейс deprecation с точной датой отключения (DR-4)
- Воспроизводимый тихий день (DR-3)
- Лог прогона с намеренно недоступным источником (DR-5)
- Доставка в Telegram живьём

Желательно, но отрезаемо: второй конфиг темы (DR-6), третья поверхность (DR-10), macOS-клиент (DR-11).

## 9. Гигиена работы

- Коммитить по завершении каждого пункта плана, не копить
- Конфиг темы и секреты разнесены: токены только в переменных окружения (NFR-11)
- Лог прогона пишется с первого запуска, а не добавляется в конце — по нему будет отлаживаться всё остальное
- При падении стадии сохранять результаты предыдущих (NFR-4): иначе отладка бэкфилла превращается в перезапуск с нуля
